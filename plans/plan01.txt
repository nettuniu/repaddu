# REPADDU - STRATEGIC & TECHNICAL ROADMAP

## 0. Nuovo obiettivo del progetto

La direzione non dovrebbe più essere semplicemente:

```text
Repository
    ↓
Markdown files
```

ma:

```text
Repository
    +
Task opzionale
    +
Git state
    +
AST / symbols
    +
Build graph
    +
Security policies
    +
Token budget
        ↓
      REPADDU
        ↓
Portable Context
```

La nuova value proposition potrebbe essere:

> **Turn any codebase into deterministic, secure and task-relevant context for humans, LLMs, agents and RAG systems.**

Principio fondamentale:

> **LLM optional, never required.**

Repaddu deve poter funzionare completamente offline e deterministicamente.

# 1. OBIETTIVI PRINCIPALI

## 1.1 Portable Context Pack

**Priorità: 10/10**
**Probabilità di valore: 95%**

Mantenere quello che repaddu già fa bene, ma formalizzarlo.

Input:

```bash
repaddu context -i .
```

Output:

```text
context/
├── 000_overview.md
├── 001_architecture.md
├── 002_core.md
├── 003_io.md
├── 004_tests.md
└── manifest.json
```

Il context pack deve essere:

* deterministico;
* versionabile;
* riproducibile;
* leggibile dagli umani;
* leggibile dalle macchine;
* indipendente dal provider;
* utilizzabile con ChatGPT, Claude, Gemini, local LLM, RAG e agenti.

### Acceptance criteria

Due esecuzioni sulla stessa repository e stesso commit devono produrre lo stesso contenuto, salvo metadata esplicitamente non deterministici.

# 2. SISTEMARE IL CHUNKING

## 2.1 Semantic chunking

**Priorità: 10/10**
**Probabilità: 97%**

È probabilmente il primo problema tecnico da risolvere.

Oggi:

```text
BigFile.cpp
    ↓
too large
    ↓
error
```

Obiettivo:

```text
BigFile.cpp
    ↓
AST
    ↓
namespace
    ↓
class
    ↓
method/function
    ↓
semantic chunks
```

Gerarchia di splitting:

```text
file
 ↓
namespace
 ↓
class / struct
 ↓
function / method
 ↓
statement groups
 ↓
line boundaries
 ↓
hard split, ultima risorsa
```

### Regola fondamentale

Mai spezzare una funzione se esiste un'alternativa.

### Metadata da preservare

Ogni chunk deve conoscere:

```json
{
    "source": "src/server.cpp",
    "start_line": 125,
    "end_line": 281,
    "symbols": [
        "Server::shutdown",
        "Server::cleanup"
    ]
}
```

### Problemi

* macro C/C++;
* template enormi;
* codice non parsabile;
* conditional compilation;
* parser non disponibile.

### Soluzione

Pipeline fallback:

```text
AST
 ↓ fail
heuristic parser
 ↓ fail
line-aware splitter
```

# Il prodotto finale ideale

Alla fine vorrei poter usare:

```bash
repaddu context \
    --input . \
    --task "Find the cause of the shutdown deadlock" \
    --diff main \
    --max-tokens 50000 \
    --context-level standard \
    --security-profile strict \
    --preset chatgpt \
    --output context/
```

e ottenere:

```text
context/
├── 000_overview.md
├── 001_changes.md
├── 002_architecture.md
├── 003_relevant_symbols.md
├── 004_shutdown_path.md
├── 005_dependencies.md
├── 006_tests.md
└── manifest.json
```

L'overview potrebbe spiegare:

```text
TASK

Find the cause of the shutdown deadlock.

TOP RELEVANT SYMBOLS

Server::shutdown
WorkerPool::stop
ThreadPool::join
Database::flush

TOP RELEVANT FILES

src/server.cpp              relevance 0.98
src/thread_pool.cpp         relevance 0.95
src/database.cpp            relevance 0.82
tests/shutdown_tests.cpp    relevance 0.91

WHY

Server::shutdown directly matches the task.
ThreadPool::join is two calls downstream.
shutdown_tests.cpp directly invokes Server::shutdown.

TOKEN BUDGET

Requested: 50,000
Used: 47,812

EXCLUDED

1,382 unrelated files
218 generated files
74 vendor files
14 binaries
3 files blocked by security policy
```

Quello per me sarebbe **repaddu 2.0**.

Non più:

```text
repository → Markdown
```

ma:

```text
repository
    ↓
understand structure
    ↓
rank importance
    ↓
understand changes
    ↓
follow dependencies
    ↓
apply security policies
    ↓
respect token budget
    ↓
produce portable context
```

## Obiettivo strategico finale

Repaddu non deve cercare di essere più intelligente di Claude o Codex.

Deve cercare di essere **più deterministico, più strutturato, più economico e più specializzato nella preparazione del codice**.

Claude/Codex possono decidere *cosa fare*.

Repaddu può diventare estremamente bravo a rispondere:

> **“Qual è il contesto minimo, strutturalmente corretto e verificabile che serve per farlo?”**

Se arriva davvero a questo punto, valuterei il progetto **9-9.5/10 con circa 90% di confidenza sul valore tecnico**, rispetto al circa **7/10 dello stato attuale**.
